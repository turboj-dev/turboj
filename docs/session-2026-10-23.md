# Implementation session — 2026-10-23

Started from an empty project directory on an Apple M5, 16 GiB RAM, macOS 26.5.1 with Amazon Corretto 25.0.4.1. No existing user source was overwritten.

## Delivered

- Real Java 25 Swing/Java2D desktop, custom piece-table editor, DOS menu layout, three JSON themes, live diagnostics, atomic UTF8 saves, external-change protection and recovery.
- Resident in-memory javac, JDT 3.44 recovery parsing, versioned snapshots, coalescing and exact-source cache. Execution remains explicit.
- Independent persistent execution JVM, Fast/Isolated Run, stdin/stdout/stderr, Stop, deadlines, bounded output and process recovery.
- GUI and CLI remote JShell, multiline submission, persistent variables/methods, diagnostics, history/completion, selection/AST-statement evaluation and process-based Stop/reset.
- `tj open/check/compile/run/eval/repl/doctor`, explicit external classpath parity, tests, JMH/end-to-end benchmarks, pinned dependency licenses and macOS packaging.

All implementation source is in `core/`, `app/`, `worker/`, `cli/`, and `benchmarks/`; build/launch/package tools are in the repository root and `scripts/`. Architectural decisions, shortcuts, themes, compiler behavior, limitations and evidence are in `docs/`.

## Verification actually executed

`./mvnw package`: **49 tests, zero failures/errors** (core 22, worker 12, app 10, CLI 5). Tests cover randomized piece-table edits/line indexes/snapshots, Unicode/CRLF, lexing, compiler errors/cache/version supersession, process reuse/crash/timeout/input/output, JShell, explicit classpaths, file fingerprints and themes.

The real-window `GuiSmoke` passed: new buffer→Hello→edit→new output, Cmd+R/F10/Escape, all themes preserving source/caret, unresolved symbols blocking Run, infinite-loop Stop, Scanner input, Isolated Run, save concurrent with Run, coalesced saves, external-write rejection, JShell lazy-start cancellation, `5*7=35`, multiline, history/Tab, selection/current statement, and REPL loop Stop/reset. It also typed 120 synthetic keys during compilation and checked the final diagnostic source version.

Repeated that entire GUI test with the **bundled runtime and bundled JAR**, successfully. `./tj doctor`, `./tj run examples/Hello.java`, `./tj check examples/Calculator.java` and `./tj eval '1 + 2'` returned real expected results. A sandboxed JShell invocation and packaging test run initially failed because local socket binding was denied; rerunning with normal local process permissions passed. No disabled test was counted as a pass.

`./scripts/package-macos.sh dmg` produced `dist/TurboJ.app` (about 86 MiB on disk) and `dist/TurboJ-1.0.0.dmg` (about 63 MiB). The application contains its runtime/compiler and was launched through macOS LaunchServices with `examples/Hello.java`; the native ARM64 launcher remained active. `codesign --verify --deep --strict` passed, and `hdiutil verify` reported a valid DMG checksum.

The native bundle version is 1.0.0 because macOS jpackage rejects a zero first component; the source product remains a 0.1.0-SNAPSHOT development preview. The signature is **ad hoc**, with no Developer ID identity, signing team or notarization. Intel binaries were not built/tested.

## Measurements and limits

Warm Hello javac p95 **11.470 ms**; already-compiled warm-worker dispatch-to-completion p95 **1.029 ms**. The visible editor-component 10,000-line synthetic key-handler-to-paint p95 was **4.152 ms**. These are different operation boundaries, not a complete Run-key or physical keyboard-to-screen measurement. Raw results and all observed GUI runs are retained; see performance.md.

The packaged full-GUI run measured 1,000-line handler/edit-to-paint p95 **1.376 ms** over 120 paints. Three 5-second native-app+worker idle samples found no CPU-time increase detectable at `ps` counter resolution. These short development samples are not release guarantees.
