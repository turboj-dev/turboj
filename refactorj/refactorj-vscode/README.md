# RefactorJ for VS Code

An explicit **RefactorJ: Refactor This** command and Java context-menu entry expose applicable semantic transformations. **RefactorJ: Rename** is separate from the built-in rename action. Quick actions are prefixed RefactorJ. Definition/reference providers coexist with other Java tooling. Requests use the same Java engine through one resident local LSP process per trusted workspace.

Set `refactorj.javaExecutable` to Java 25. Source roots and classpath are optional project settings; dependency discovery is not inferred from arbitrary build scripts. Named operations prompt for a name; complex operations expose the complete typed JSON request fields. A native diff opens for each affected file, followed by explicit approval before one WorkspaceEdit is applied. Unsaved buffers and source versions are checked; cancelled or stale results do not apply. The extension never executes source or calls Save during a refactoring. VS Code itself persists dirty working copies during file moves/deletes, so those resource operations require the user to save the affected file explicitly first. Text-only refactorings support unsaved buffers. Native undo restores the path and editor text. VS Code leaves the undone text dirty; use Save to persist that undo to disk. Its resource service may persist the refactored text during a move, so disk-only rollback is not claimed for the extension.

Build the parent Maven modules and `python3 ../scripts/package.py`, then `npm ci`, `npm run package`. Install the generated VSIX using **Extensions: Install from VSIX**. Run `npm run test:host` against a real VS Code installation; `CODE_EXECUTABLE` selects an alternate executable and `REFACTORJ_TEST_JAVA` selects Java 25. The isolated profile disables telemetry and automatic updates and leaves user settings untouched. Host results are in `artifacts/host-test-result.txt`.

The source package requires Node 22+ and the pinned TypeScript/VS Code SDK dependencies. The installed extension needs Java 25 but neither TurboJ nor Node developer tools. It does not replace Java formatting providers. Multiple project roots use independent resident workspaces; cross-root refactorings are rejected.

Verified on VS Code 1.138.0: 19 actual host assertions cover preview purity, unsaved text apply/undo/redo, stale/cancelled requests, resident reuse, dirty resource guards, file rename, path/text undo, and explicit save after resource undo. The test does not claim every semantic operation was exercised in the host; the shared engine has its own correctness suite.
