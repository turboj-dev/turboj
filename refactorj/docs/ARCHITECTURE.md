# Architecture

The authoritative model is one headless Eclipse Java project per active workspace. `LtkWorkspace` owns Java model configuration, unsaved working copies, semantic bindings and bounded caches. `SharedJavaIntelligence` uses those same working copies for IntelliSense, navigation, documentation, signature help and test selection. TurboJ's existing `JavaIntelligenceService` is a compatibility facade; it does not build a parallel project index.

The immutable `JavaSemanticWorkspace` API provides snapshots, symbol resolution, references, hierarchy and symbols. `RefactorJ.prepare` analyzes a typed request, runs Eclipse initial/final conditions, converts the preview `Change` tree into immutable text/file edits, and verifies candidate diagnostics against baseline diagnostics. Candidate files are parsed together using a secondary working-copy owner so cross-file changes resolve to the proposed source. Preparation does not call `Change.perform` on user files. Repeated validation of the exact immutable plan may reuse the validated result; configuration/source changes invalidate caches.

`refactorj-runtime` loads intact Eclipse bundle JARs in an embedded Equinox framework. This preserves OSGi manifests even inside a shaded application or IntelliJ plugin. It is a library runtime within the host JVM, not an external process, server or Eclipse UI. The public API shares the host class loader; mutable compiler implementation classes remain isolated. The small PLURL URL-handler facade is shared with the host because Java URL hooks are JVM-wide. Context class loaders are restored after initialization. Frameworks, model resources and private temporary storage are released on close.

`refactorj-transactions` has no Eclipse/UI dependency. It validates content and versions, composes sparse UTF-16 changes and delegates publication to a `WorkspaceStore`. `InMemoryWorkspace` supports editor buffers. `DiskWorkspace` provides journaled closed-file changes with explicit recovery. It never claims atomicity across an entire filesystem. Source journals are private local data and must not be committed or uploaded.

The optional `refactorj-formatj` adapter formats generated replacement regions and generated files through the existing Java formatter. It composes formatting edits back into original coordinates without reformatting unrelated declarations. Formatting failure preserves the semantic plan. No formatting dependency appears in the pure semantic API.

CLI, LSP and MCP depend on the public API/runtime and transactions. IntelliJ embeds the API when its Java runtime is compatible and offers an explicit resident compatibility backend. VS Code uses a resident LSP process. TurboJ does not depend on these protocol adapters. CommandJ has no dependency on RefactorJ, Eclipse or Java semantics.
